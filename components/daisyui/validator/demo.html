表单校验 Validator

纯 CSS、零 JS：给输入框加 validator，配合原生 required / pattern / minlength，填对变绿、填错变红，下方 validator-hint 写清规则。下面先给一个修改密码的成品，再列出常见规则供参考。

三步用到你项目里

  1. 在页面里引入两行样式：daisyui.css 和 utilities-patch.css（本项目都已打包，零依赖、无需构建）。
  2. 首选点「复制 AI 提示词」，整段发给你的 AI，它会结合你的项目直接生成；想自己粘贴代码，再用「复制成品 HTML」，保存成 .html 双击即可预览。
  3. 改校验规则只改 required / pattern / minlength 这些原生属性即可；切换主题后，成功绿与错误红会自动跟着变。
成品示例 · 拿来即用

账号设置里的修改密码区

两个密码字段各自用 fieldset 包起，输入框加 validator，规则靠原生 required、minlength、pattern 声明；下方 validator-hint 把规则说成人话，失焦或提交时自动变绿/变红。底部放确认修改按钮。

设置新密码

至少 8 位，且同时包含数字、小写字母和大写字母

确认新密码

两次输入需要完全一致（一致性比对需一行脚本，此处仅占位提示）

首选「复制 AI 提示词」整段发给你的 AI，它会按你的项目生成；想直接粘贴代码、双击预览，再用「复制成品 HTML」。

邮箱格式校验

用 type="email" 加 required：浏览器自带邮箱格式判断，输入非法（如只打 abc）失焦后框变红，提示写在下方 validator-hint。

请输入有效的邮箱地址，例如 name@site.com

用户名规则校验

用 pattern 写正则、minlength / maxlength 限长，规则逐条写进 validator-hint，比弹一次浏览器提示清楚得多。

3–30 个字符，只能包含字母、数字或连字符，且以字母开头

手机号 11 位

type="tel" 调出数字键盘，minlength / maxlength 锁 11 位；数字用 tabular-nums 等宽对齐，观感更稳。

请输入 11 位手机号，用于接收登录验证码

必勾协议校验

checkbox 也能加 validator 配 required：未勾选就提交时，这一项会标出错误；validator-hint 说明必须勾选才能继续。

勾选后才能继续注册

内嵌图标的校验输入

图标放进外层 label.input.validator，真正的输入框加 grow；校验样式同样生效，适合带前缀图标的搜索、卡号等字段。

3–30 个字符，以字母开头，可含数字或连字符

使用指南

校验靠原生属性，不写 JS

给控件加 validator 类，规则写在原生 required、type（email/tel/url/number）、pattern、minlength、maxlength、min / max 上。daisyUI 据此在用户触碰并离开（或提交）时自动把合法项变绿、非法项变红，不需要任何脚本。

每个字段独立成组

一个字段 = 一个 fieldset，里面放控件和它自己的 validator-hint。多个字段别共用一层容器，否则错误提示容易串到别的字段上。

提示要写人话

validator-hint 始终占位显示规则，不要只让框变红却不写清错在哪、怎么改。把规则拆成短句（长度、字符类型、格式），比一句话正则好懂。

纯 CSS 做不到的，别硬凑

  • 「两次密码一致」属于跨字段比对，原生 CSS 做不到，需要一行脚本；本页只放占位提示，不要假装它能自动校验。
  • 实时强度条、异步查重（用户名是否已被注册）都需要 JS，不属于本组件范围。
  • 前端校验只是体验优化，最终合法性必须在服务端再验一遍，不能只靠它。

常见坑

  • pattern 用正则，注意转义；同时配 title，浏览器原生提示会用到它。
  • 错误红 / 成功绿只在用户触碰后出现，这是 :user-invalid 行为，不是 bug；想让首次进入就标红需要自己加状态类。
  • 不要为了醒目给每个输入都加状态色，只在校验结果明确时才用。
