# 素材引入与许可证政策

> 灰墨 MoH_UI 是**开源、非商用**项目。我们大量借鉴海外开源项目的主题、组件与设计方法，这不只是"合理"，在开源社区它就是正常协作方式。但"不谨慎怕抄袭"和"乱抄"之间有一个专业中间态：**逐项核对许可证、保留版权声明、建素材清单**。本文是这一中间态的落地规则。

## 1. 原则

1. 本项目 MIT License（© 2026 noii-y），我们引入的一切素材**必须保留原版权声明**；
2. 每个引入素材在 `moh.json` 的 `source` 字段登记：原项目名 / 地址 / 许可证 / 改动说明；
3. 全库汇总进 `ATTRIBUTIONS.md`，与 `moh.json` 保持一致；
4. **禁止**的行为：搬运商业产品品牌资产（Logo / 名称 / 商标）、1:1 克隆商业产品整体外观、引入含"Commons Clause"等附加限制的代码后打包售卖（本项目不售卖，但条款仍要避免）。

## 2. 许可证对照表（引入前必查）

| 许可证 | 能不能用 | 要求 | 结论 |
|---|---|---|---|
| **MIT** | ✅ | 保留版权声明 | 直接用，署名即可 |
| **Apache-2.0** | ✅ | 保留 LICENSE + NOTICE（如有）+ 标注改动 | 直接用，署名 + 改动说明 |
| **GPL-2.0 / GPL-3.0** | ✅ | 衍生作品须以相同许可证开源（传染） | 可用；该素材对应的我们文件标 GPL，不与 MIT 主体混装 |
| **LGPL** | ✅ | 修改库本体须开源，链接不受限 | 可用；修改库本体时按 GPL 对待 |
| **CC-BY-4.0** | ✅ | 署名 | 可用，署名即可 |
| **CC-BY-NC / CC-BY-NC-SA** | ✅ | 不得商用 | 本项目非商用，可用；若未来商用需换素材 |
| **CC0 / Unlicense / 公共领域** | ✅ | 无 | 最自由 |
| **ISC / BSD-2 / BSD-3** | ✅ | 保留声明（BSD-3 还有禁止背书条款） | 可用，署名即可 |
| 品牌资产（Logo/名称/商标） | ❌ | — | 一律不搬，即使该代码 MIT |
| 专有 / 未声明许可证 | ❌ | — | 默认不可用（除非作者明确授权） |

## 3. 引入流程（每个素材必走）

```
① 找到原项目 → ② 确认许可证（仓库 LICENSE 文件 / npm 页面 / 官网声明）
→ ③ 记入 moh.json source 字段（upstream/url/license/changes）
→ ④ 保留原版权声明到我们的文件头注释
→ ⑤ 更新 ATTRIBUTIONS.md 汇总行
→ ⑥ 跑 scripts/check-attributions.mjs 校验通过
```

## 4. 特别说明

- **"附原组件名称和地址 + 教程转中文"是我们定下的工作方式**：素材本体按上表合规引入，教程与介绍是我们原创的中文内容，不受素材许可证限制；
- **方法论的借鉴**（如 Taste Skill 的规则化审美、shadcn 的 registry 机制）不受版权约束，但我们在文档中注明参考来源（已在各文件头注释中声明）；
- 任何拿不准的许可证，**先问再引入**，不要赌。

## 5. 本仓库当前素材状态

全部为**自研**（origin=original，MIT），引入海外素材后按本文第 3 节流程登记。汇总见 `ATTRIBUTIONS.md`。
