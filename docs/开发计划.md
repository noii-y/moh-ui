## 一、项目定义（定稿 2026-10-16）

### 1.1 一句话定位

**"给 AI 搭出来的后台 / 管理系统做审美整容 + 中文 AI 内容库"**：三层内容——① **规则边界包**（AI 不容易察觉的"整容"：字号/表格/间距/对齐/对比度硬边界 + 禁则，指令 + 自查闭环，中文+后台场景无人占住）；② **丰富视觉效果主题库**（多种风格可选，全部统一接入 `--moh-*` 变量，AI 一句话换肤）；③ **组件 / 插件库**（基础组件零依赖 + 增强组件可带依赖，用户能搬到自己的项目）。素材策略：借鉴海外开源项目，附原组件名称与地址、教程与介绍转中文挂在灰墨下；开源非商用、二创合理、署名溯源。叙事卡位仍为"**Taste Skill 不做的那一半**"（Taste 官方声明不做 dashboard / app UI）。

### 1.2 项目定义表

| 维度 | 定义 |
| --- | --- |
| 主打方向 | ① 规则边界包（AI 不易察觉的审美"整容"，附带服务但差异化最大）② 丰富视觉效果主题库（多风格可选，统一 `--moh-*` 接入，主打）③ 组件/插件库（基础零依赖+增强可带依赖，可搬到用户项目，主打） |
| 技术 | CSS 变量主题包（全部统一 --moh-*）+ 原生 HTML 单文件组件 + 静态展示站 + Node 清单/校验脚本（体检/组件/站点/素材四件套）+ AI 指令链接/MCP/CLI 三入口 + moh.json 资源元数据（素材溯源） |
| 目的 | 用户价值：不会设计的人让 AI 按规则"整容"自己的后台，并从丰富主题/组件库里挑选搬到项目；项目价值：内容多、使用率高，持续运营的 GitHub 代表作与求职竞争力；商业化：先纯开源做口碑 |
| 受众 | 主：用 AI 搭后台/SaaS/内部工具但不会设计、前端弱的中文开发者；次：前端初学者、求职者 |
| 平台与应用 | 平台：豆包/Cursor/Claude Code/Codex/v0/Lovable 等全部 AI 工具；应用：后台管理、SaaS 控制台、数据看板、内部工具、表单密集型应用；技术栈：原生优先、Vue 二期、React 走 shadcn registry |
| 巧思 | ① 规则边界"AI 不容易察觉的整容"（中文+后台场景无人占住，含禁则一票否决）② 主题全部统一转 --moh-* 变量（任何来源主题一句话换肤，体验一致）③ 素材署名溯源机制（moh.json + ATTRIBUTIONS.md + 校验脚本，"抄得专业"）④ 零门槛 AI 指令链接（丢链接即用）⑤ 审美体检闭环（主题/组件/站点/素材四套自检，<90 不许发布） |
| 强在哪 | 组合优势：规则边界（中文×后台×可执行）× 主题丰富度（多风格×统一接入）× 素材合规（署名×非商用×可追溯）× 零门槛——单点不比头部，组合无人占住 |

### 1.3 两个反问（想透这题项目才成立）

1. 为什么不用 shadcn 官方主题？→ 需 React+Tailwind+Node 工程环境；我们的受众很多是原生 HTML/Vue 单文件，装不起。
2. 为什么不用 antd pro / AdminLTE 后台模板？→ 那些是**给人**的人工模板，要手动集成、绑定 React 全家桶/Bootstrap 老生态；我们做的是**给 AI** 的皮肤包，AI 能自己"伸手拿"。

### 1.4 项目形态（定稿：三层结构，不是传统"网页/插件/应用"）

| 层 | 是什么 | 作用 |
| --- | --- | --- |
| 内容仓库（核心） | GitHub repo：`themes/` + `components/` + `scripts/` + `mcp-server/` | **货**：皮肤包与组件的实体 |
| 静态展示站（门面） | 网页：预览全部皮肤/组件、复制按钮、AI 链接页、**可视化主题选择器（必做）** | **橱窗**：访客 / 引流 / 求职门面 |
| AI 分发通道 | AI 指令链接 + MCP Server + 轻量 CLI | **送货**：让 AI 自己拿到货 |

**明确不做**：浏览器插件（Chrome 扩展不符合 AI 工作流）、IDE 插件（VS Code 插件生态正被 MCP 取代）、独立桌面应用（TasteCode 模式，无必要）。用户场景是"AI 编程工具在工作时获取皮肤"，AI 生态的标准接口是链接 / MCP / CLI。

**必做增强（用户确认 2026-10-16）**：展示站含**可视化主题选择器**——选主题 → 实时预览 → 一键生成 tokens.css（可调主色/圆角/密度）→ 复制 / 下载。排期：P1 展示站先含"预览 + 复制 AI 指令 + 纯文本版"，选择器 P2 随主题参数定稿后实现（依赖 5.2 主题规范稳定）。

### 1.5 使用方式（定稿：三条路径）

**路径 1 丢链接（零门槛，主路径）**：打开展示站 → 找到心仪主题/组件 → 点"复制 AI 指令" → 把指令（含链接）贴给豆包/Cursor → AI 抓取并集成。
- **兜底**：不是所有 AI 都会主动抓 URL（豆包网页版行为待实测）→ 每个 AI 链接页同时提供"纯文本版"内容，AI 不抓链接时用户可直接复制粘贴全文。

**路径 2 CLI（开发者）**：`npx moh-add theme mo-dark`（直拉文件，无 node_modules，参照 arniejsc 模式）。

**路径 3 MCP（AI 原生）**：配置一次后直接说"把后台换成灰墨深色"，AI 调工具完成。

### 1.6 自检机制（定稿：双层自检 + 修复闭环）

**内容层（发布前，保证"货"的质量）**
- 体检脚本 v1：**纯 Node 静态检查，不需要浏览器**（对比度 / 字体栈 / 间距网格 / 禁硬编码 hex / 反 AI 味）→ 0–100 分，**<90 不许发布**；Playwright 截图版后置 P3
- 每个组件/主题发布前必跑；后续挂 CI

**使用层（应用后，保证"装上能用"）**
- AI 链接页自带"应用后自检清单"：AI 装完自查 5 项（文件写入、变量生效、组件渲染、对比度、无报错）
- **预期快照**：每套主题的 preview.html 是基准，AI 应用后对照
- P2 加 `sk-verify` 安装验证脚本（检查 tokens.css 存在、类名引用、抽样对比度）
- 开发时在豆包 / ChatGPT / Cursor 实测，沉淀"成功提示词模板"

**闭环**：AI 交付 → 自检脚本 → 不达标修复（最多 3 轮）→ 达标 → 截图留档。

### 1.7 内容版权边界（定稿：什么可以抄&搬运）

| 可以搬（合规） | 不可以搬（风险） |
| --- | --- |
| 开源代码（MIT/Apache：Taste 规则文本、StyleSeed 结构、shadcn schema、awesome-design-md）——**带署名 / 保留版权声明** | 品牌资产：Logo、商标、文案、图片素材 |
| **抽象设计 token**（颜色/字体/间距/圆角等风格参数）——行业惯例，Linear/Stripe token 已在多个 MIT 仓库公开提取 | 闭源产品 CSS/源码直接复制（引用 MIT 仓库里的提取值可以，直接抄产品站点的 CSS 文件不行） |
| 参考思路、原创实现 | AGPL 代码（归藏/甲木）；1:1 克隆整站版式（整体视觉呈现有版权争议）；Commons Clause 项目（React Bits）打包售卖 |

**合规流程**：只用公开有许可的素材源 → 组件代码全部原创 → 每套主题附"设计来源说明"（参考了谁、什么许可）→ README 附版权与来源声明。

## 二、背景与机会

### 2.1 现象

- 2026 年 vibe coding 大爆发，大量非专业开发者（独立开发者、创业者、学生、自媒体、接单的人）用 AI 直接生成网站、后台、SaaS。
- 但 AI 生成的页面高度同质化：紫色渐变、圆角卡片、无层次的排版、间距随意，社区普遍吐槽"一眼 AI 味"。
- 用户已形成新习惯：在组件网站看到心仪效果 → 复制代码 → 丢给 AI 编程助手集成。抖音上多条"UI 动效网站 / 组件库"视频播放与点赞很高，需求真实且旺盛。

### 2.2 需求洞察

- 痛点不是"没有组件"，而是"**AI 生成的系统整页都丑**"，以及"**把好看的组件喂给 AI 这一步太麻烦**"。
- 现有工作流是断的：找组件 → 复制代码 → 粘贴回 AI → 说明怎么改，至少 4 步。
- 机会：把"找组件、取代码、装依赖"这几步也交给 AI，让 AI 自己"伸手去拿"。

### 2.3 对个人价值

- 持续运营型仓库：组件/主题每周新增，天然有更新理由，Star 持续增长。
- 自带在线 Demo 网站：访客打开就能看到效果，是最直观的"门面"。
- 求职可讲：前端工程化 + 设计系统 + 工具链（CLI/MCP）三方面能力的综合展示。
- 踩中 2026 最热的 MCP / AI 工具生态，面试时是新鲜话题。

### 3.2 空位结论（定稿）

所有新玩家共享三个缺口：
1. **不做或没做透后台 / 管理系统 / 应用 UI 场景**（Taste 官方让出、StyleSeed 仅 React 触碰、Better Design 门槛过高）。
2. 交付**规则 / 文档**居多，缺少"现成组件 + 整套主题实体一键应用"。
3. **零门槛 AI 指令链接**形态无人认真做（所有人都是 Skill / MCP / CLI，要先安装）。

**定稿定位**：AI 应用的后台/管理系统界面"审美急救"——交付现成组件与整套主题实体（非规则），主攻中文与零门槛分发；首发主题为**高级极简后台风**；首发技术栈为**主题包优先**（CSS 变量 + 单文件组件 + AI 链接）。

### 3.3 执行策略：融合路线（定稿）

**决策**：独立仓库 + 代码全部原创；方法论借鉴 Taste Skill（MIT），架构参考 StyleSeed（MIT，可共建），分发借鉴 Wot UI 三入口；**叙事上借 Taste Skill"不做后台"的官方声明卡位**（README 互认），不 fork、不复制任何上游代码。

| 层 | 借（来源） | 不借（原创增量） |
| --- | --- | --- |
| 方法论 | 审美规则化 + 浏览器自检闭环（Taste Skill，MIT；只参考架构，不抄代码） | 后台/应用 UI 专属规则集（表格/表单/导航密度等，Taste 官方明确不做） |

**借势落地动作**
1. README 首屏明确写："Taste Skill 让 AI 做出好看的营销页；本项目让 AI 做出好看的后台。Taste 官方明确不做 dashboard / app UI，这块我们来做。"并放 Taste 仓库链接（互认引用，非竞争性）。
2. 架构说明页写清借鉴来源与协议（MIT 合规：参考思路 + 原创实现，逐项标注）。
3. 可选：给 StyleSeed 提交"原生 HTML 后台主题包"PR，建立共建关系后 README 互链。

## 四、技术方案

### 4.1 形态 A：AI 指令链接（零门槛，P1 首发）

- 每个组件 / 每套主题有一个"AI 友好链接页"，返回干净的 Markdown / JSON：组件完整代码、依赖及安装命令、props 说明、接入步骤（原生 / Vue 两版）、适用场景。
- 用户把链接贴进任意 AI 对话框："帮我把这个组件加到我的首页：https://你的域名/ai/marquee"。
- 任何 AI（豆包、ChatGPT 网页版、Cursor 等）都能抓取并集成，无需安装任何插件。
- 技术要点：结构清晰、无多余 HTML 噪声、代码块完整，AI 抓取后无需二次猜测（详见 6.3-②）。

### 4.2 形态 B：shadcn Registry + 轻量 CLI（P2）

- 遵循 shadcn 官方 registry 规范（官方明确 registry 可以是 Vue、Svelte、PHP 或任何框架，只要能通过 HTTP 提供 JSON，也可直接用根目录放 `registry.json` 的公开 GitHub 仓库）。
- 核心文件：`registry.json`（入口，含 items 列表）+ 每组件一个 `registry-item.json`（关键字段：type / files / dependencies / registryDependencies / **cssVars（皮肤包关键）** / css / docs）。
- 安装：`npx shadcn@latest add https://你的域名/r/组件名.json`；可提交 PR 进入官方目录获得导流（可选，P3 评估）。
- **兜底**：shadcn CLI 对 React 支持最成熟，Vue / 原生以"符合 schema 的 JSON + 自研轻量安装脚本"过渡（参照 arniejsc 模式：`npx <包名> add 组件名` 直拉文件，无 node_modules）。

### 4.3 形态 C：MCP Server（P2）

- 协议：MCP（JSON-RPC 2.0），已被 Claude Desktop、Claude Code、Cursor、Cline、TRAE、Windsurf 等全线支持；本项目主要用 Tools 能力。
- 实现：Node.js + `@modelcontextprotocol/sdk` + zod；`new McpServer(...)` → `server.tool(...)` → `StdioServerTransport`；本地 STDIO 约 30 分钟可跑通。
- 建议暴露工具：`list_categories()` / `search_components(query, framework?)` / `get_component(name, framework?)` / `install_component(name, framework?)` / `list_themes()` / `apply_theme(name)`。
- 工具返回内容设计为"自包含"：AI 拿到一次结果就能完成集成，无需反复询问。
- 客户端配置：统一在 `mcp.json` 的 `mcpServers` 中配置（Claude Desktop / Claude Code / Cursor / 项目级 `.mcp.json`）。

### 4.4 形态 D（可选·主题生产）：设计 DNA 提取器

- 解决"整套主题从哪来"：输入任意好看的网站 URL → headless 浏览器（Playwright）读取真实计算样式 → 提取设计 token（配色、字体、字号阶、间距基准、圆角）→ 转成 CSS 变量 / shadcn `registry:theme` JSON。
- **合规红线**：只提取抽象的"设计语言"（颜色/字体/间距等不受版权保护的风格），不复制页面结构、文案、图片、Logo、品牌资产；不做整站 1:1 克隆；遵守 robots 与 ToS，限频、限同域。
- 与 A/B/C 的关系：A/B/C 是"主题的分发与应用"，D 是"主题的生产与输入"，闭环：`看到好看网站 → 提取设计 DNA → 生成主题 → AI 一键应用到用户系统`。
- 最小实现（新手友好）：第一版只抓 5 个字段（主色、字体、字号阶、间距基准、圆角），输出一个 CSS 变量文件 + 静态预览页。
- 额外价值：批量分析知名网站、产出"这个网站为什么好看"的拆解图，是天然的短视频引流内容。
- **已定稿：不纳入 MVP（P0–P3 不依赖它），作为 P3 之后的引流与主题扩充工具。**

### 4.5 技术栈与原则

- 组件内容：**原生 HTML/CSS/JS 起步**（零依赖、受众最广、最容易验证），第二阶段补 Vue 3。
- 展示网站：Vite + 简单静态站点（或 VitePress / Astro），部署到 Vercel / Cloudflare Pages（免费）。
- 清单：脚本扫描组件目录，自动生成 `registry.json`、每组件的 `[name].json` 和 `/ai/[name]` 页面。
- MCP：Node.js + `@modelcontextprotocol/sdk`，初期 STDIO 本地版，后期远程 HTTP 版。
- 原则：**不发明新协议，全部复用 shadcn registry schema 与 MCP 标准。**

### 5.2 主题包规范（核心资产）

每套主题一个目录 `themes/<name>/`：

```
tokens.css        # CSS 变量：色板(--bg/--surface/--text/--primary…)、CJK 字体栈、字号阶、间距(8px 基线)、圆角、阴影、动效曲线
base.css          # reset + 排版 + 布局基础
components.css    # 后台组件样式（统一前缀 sk-，如 .sk-table / .sk-card / .sk-sidebar）
preview.html      # 单文件预览（双击即开，含全部组件展示）
metadata.json     # 机器可读：name/version/依赖/接入步骤/一句话描述/AI 指令模板
README.md         # 接入文档（原生 / Vue 两版）
```

- 组件命名空间统一 `sk-` 前缀；变量命名规范以 tokens.css 模板为准。
- 同时输出 shadcn `registry:theme` 兼容 JSON（cssVars 字段映射，见 4.2）。
- **换肤机制**：所有组件样式只引用 CSS 变量 → 换主题 = 换 tokens.css，组件代码零改动。

### 6.3 应用效果怎么验证（不靠想象，真测）

**① AI 集成测试矩阵（P1 验收必做）**

- 工具至少测 3 个中文用户常用：豆包网页版 / 豆包工作 / ChatGPT / Cursor（任选 3）
- 场景：新建页面应用主题 / 给已有页面换肤 / 集成单个组件
- 判定：AI 是否一次成功、是否乱改 token、代码是否完整、依赖是否装对

**② AI 链接页设计规则（让 AI 一次成功，这是形态 A 成败的关键）**

- 一页只讲一件事（组件或主题），无导航/广告噪声
- 代码块完整可整段复制：CSS 变量、组件 HTML、接入说明分块
- 自包含：页面自带"如何应用"步骤（原生/Vue 两版），AI 无需二次猜测
- 纯文本可抓取：不依赖 JS 渲染、图片懒加载
- 给出明确的"建议文件路径"（如 `assets/tokens.css`）

**③ 后台版体检检查项清单（照 Taste house rules + StyleSeed 74 规则 + HTML-Anything 规范改写）**

- 对比度：正文 ≥4.5（WCAG AA）
- 字体：CJK 栈、≤2 种字体族、字号 ≤5 级
- 间距：8px 网格
- 禁：硬编码 hex（必须 var()）、默认紫**渐变**、emoji 当图标、图标芯片、全偶网格同权重卡片、纯黑 #000/纯白 #fff、无 :focus 态、lorem ipsum
- 表格：密度一致、数字右对齐、空态有文案
- 表单：校验态三色（正常/错误/禁用）、label 可见关联
- 导航：当前项高亮、层级清晰
- 闭环：AI 交付 → 脚本打分（0–100，<80 修复）→ 截图复核 → 修复循环（最多 3 轮）

**④ 真实案例素材库（内容引流核心，P1 就要开始攒）**

- 用豆包/Cursor 真实生成 3–5 个"默认 AI 后台"并截图（丑的样子）
- 应用主题后截图 → 前后对照图 = 短视频/掘金素材
- 保留提示词与生成过程 = 教程内容

| **diff** | 设计改版「优化前/后」对比：`figure.diff aspect-video` + `diff-item-1/2`（渐变+SVG 模拟两张设计稿）+ `diff-resizer` 静态 50% 分隔 | 图片对比、文字对比（bg-primary / bg-base-200 大字） | **拖动分隔线需一小段 JS**（成品静态展示；指南诚实写"拖动需 JS"，给出可选 JS 说明，不硬内置） |
| **hover-gallery** | 电商商品卡多角度图：`card` + `figure.hover-gallery`（内联渐变+SVG 产品图×3，hover 横滑换图）+ 商品名/价格/加购 | 纯画廊（4 图）、卡片内商品画廊（max-w-60） | 无（纯 CSS hover）；换真图教程 |
| **mask** | 团队页成员头像展示：一排 `mask mask-circle`/`mask-squircle`/`mask-hexagon` 渐变头像（内联 SVG 人像简影占位） | 全部 14 种形状：squircle/heart/hexagon/hexagon-2/decagon/pentagon/diamond/circle/star/star-2/triangle/triangle-2/3/4 | 无 |
| **text-rotate** | SaaS hero 标语轮换：一句话里 `text-rotate` 轮换 3 组词（写文案/做设计/写代码），大字 text-6xl/7xl 居中 | 3 词默认 10 秒、6 词大字 justify-items-center、句子混排彩底（bg-teal-400/bg-red-400/bg-blue-400 + 对应深色文字）、自定义行高（内联 line-height） | 无（纯 CSS 循环动画，hover 自动暂停）；动画时长用内联 `style="animation-duration:…"` |

**零外链铁律不变**：diff 两张"设计稿"、hover-gallery 商品图、mask 头像一律内联渐变 + SVG 占位，教程教换真图；不做可识别商标。

**公共类落点（已补 commit 38c23d4）**：`text-7xl/8xl/9xl`、`w-60/max-w-60`、`justify-items-center`、`bg-teal-400/bg-blue-400`、`text-teal-800/text-blue-800/text-red-800/text-orange-500/600` 在补丁；`aspect-video/aspect-square`、`place-content-center`、`px-2`、`bg-red-400/text-red-400/text-orange-400` 已有。`duration-*`（动画时长）与 `leading-[2]`（行高）用内联 style，不补类。

**动画边界**：aura 旋转、text-rotate 轮换、mask 无动画、diff 静态、hover-gallery hover 切换——全部在 vendor 动画豁免范围（组件自带功能性状态动画，COMMON_RULES 豁免覆盖）；成品截图必须能直接看到效果（aura 光晕、text-rotate 当前词、hover-gallery 第一张、diff 分隔线、mask 形状）。
